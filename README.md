# Robinhood Chain volume alerts

Телеграм-бот: присылает уведомление, когда **любой** токен в сети Robinhood Chain
проторговывает 300k+ USD за одно временное окно (по умолчанию — за 1 минуту).

## Как это работает

Прямой перебор всех токенов или прослушивание всех транзакций сети для такой
задачи не нужны. Используется воронка из двух шагов:

1. **Отсев.** Несколько запросов в минуту отдают пулы сети сразу вместе с
   готовым 5-минутным объёмом (см. «Глубина охвата» ниже). Если токен сделал
   300k за минуту, его 5-минутный объём гарантированно не меньше 300k — значит
   среди просканированных пулов кандидата пропустить невозможно. Всплеск
   остаётся видимым в 5-минутном окне около 5 опросов подряд, так что задержки,
   разрывы связи и упор в лимит API не приводят к потере события.
2. **Подтверждение.** Только для прошедших отсев (обычно их ноль) запрашивается
   точная свеча нужного размера и проверяется объём именно за это окно.

Данные берутся из публичного REST API GeckoTerminal (сеть `robinhood`), без
индексатора, платных стримов и API-ключей.

### Глубина охвата

Пулы запрашиваются отсортированными по объёму за 24 часа. Минута входит в сутки,
поэтому пул с суточным объёмом ниже порога не может дать всплеск на пороге — и
обход останавливается, как только страница заканчивается ниже порога. На тихой
сети это 1–2 запроса за цикл и полный охват.

Robinhood Chain сейчас не тихая: даже на 200-м по обороту пуле суточный объём
около $1.1M, то есть до порога обход не доходит. А публичный API с облачного IP
выдерживает лишь несколько запросов в минуту — обойти все страницы каждый цикл
не получится.

Выход в том, что полный обход и не обязан укладываться в один цикл. След
всплеска (5-минутный объём выше порога) живёт пять минут, поэтому каждую
страницу достаточно навещать **быстрее пяти минут**, а не каждую минуту. Цикл
сканирует `HOT_PAGES` первых страниц всегда и ещё `ROTATING_PAGES` страниц по
очереди. При настройках по умолчанию это 4 запроса в минуту, все 8 страниц
(160 самых оборотистых пулов) обходятся за 3 минуты — с запасом до пяти.
Бот пишет при старте, за сколько секунд он обходит всё, и предупреждает, если
настройки выходят за пять минут.

### Трендовые пулы

У обхода по суточному обороту есть слепая зона: свежий токен может торговать
на 300k прямо сейчас, но по сумме за сутки стоять далеко за пределами
`MAX_POOL_PAGES`. Поэтому каждый цикл дополнительно запрашивается список
трендовых пулов сети (`trending_pools`, ранжирование по свежей активности, а не
по суточному объёму) — один запрос, и именно там появляются молодые токены.

Списки объединяются и дедуплицируются по адресу пула. Если запрос трендов
падает, цикл продолжает работать на обходе по страницам. Отключается через
`USE_TRENDING=0`.

Пул, который не попал ни в трендовые, ни в пределы `MAX_POOL_PAGES`, всплеск не
покажет: это осознанный компромисс, а не гарантия.

Каждое событие отправляется один раз: алерты дедуплицируются по паре
«пул + метка времени свечи».

## Запуск

```bash
cp .env.example .env   # заполнить TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID
npm run start:local
```

Зависимостей нет, `npm install` не нужен — только Node.js 20.6+.

При старте бот отправляет в канал сообщение «Бот запущен» — это подтверждает,
что токен и chat_id указаны верно, не дожидаясь первого алерта.

### Telegram

1. Создать бота у [@BotFather](https://t.me/BotFather) → получить токен.
2. Добавить бота в канал администратором с правом отправки сообщений.
3. `TELEGRAM_CHAT_ID` — `@имя_канала` для публичного канала, иначе числовой id
   (например `-1001234567890`).

## Настройки

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | — | Токен бота (обязательно) |
| `TELEGRAM_CHAT_ID` | — | Куда слать алерты (обязательно) |
| `NETWORK` | `robinhood` | Сеть в терминах GeckoTerminal |
| `VOLUME_THRESHOLD_USD` | `300000` | Порог объёма в USD |
| `WINDOW_MINUTES` | `1` | Размер окна: `1`, `5` или `15` |
| `POLL_INTERVAL_SECONDS` | `60` | Как часто сканировать сеть |
| `BLACKLIST` | пусто | Пулы без алертов, через запятую |
| `USE_TRENDING` | `1` | Смотреть трендовые пулы (`0` — выключить) |
| `MAX_POOL_PAGES` | `8` | Глубина охвата, по 20 пулов на страницу |
| `HOT_PAGES` | `2` | Страницы, сканируемые каждый цикл |
| `ROTATING_PAGES` | `2` | Сколько остальных страниц брать за цикл |
| `MAX_CANDIDATES_PER_CYCLE` | `10` | Предохранитель на число проверок за цикл |

Стабильные и «крупные» пары (например `USDG / WETH`) дают большой объём, но
щиткоинами не являются — их отключают через `BLACKLIST`. Запись в списке
совпадает по названию пары, по символу базового токена или по адресу контракта,
регистр и пробелы не важны: `BLACKLIST=USDG / WETH, USDC`.

300k **за одну минуту** — очень высокая планка (это темп ~$430M в сутки), так что
срабатывания будут редкими. Порог и окно меняются через переменные окружения без
правки кода: например `VOLUME_THRESHOLD_USD=300000` + `WINDOW_MINUTES=5`.

## Деплой

Нужен любой хостинг, где процесс работает постоянно. В репозитории есть
`Dockerfile`; на Railway/Fly/VPS достаточно задать переменные окружения из
`.env.example`. Секреты задаются только через переменные окружения — `.env`
в git не попадает.
